Complete formats and examples from the original manual, with Z06 module-addressing updates.

Source

Based on the 20-page PSVITACHEAT Cheatfile Manual · v360.z04 Beta (Simplified Chinese). B2 and encoding updates come from the Z06 site. Version differences and original example errors are explicitly noted.

01

.psv

Cheatfile structure

Manual p. 3

Name the file after the game's Title ID, for example PCSH00297.psv, and place it in ux0:vitacheat/db/. Check the Title ID and version in sce_sys/param.sfo.

A file contains game information, entry names, and code lines. Consecutive code lines under one entry form a single cheat.

FieldMeaningDetails
#Game information or commentInclude the Title ID, game name, and version.
_V0 nameEntry OFF by defaultThis is the original VitaCheat file meaning.
_V1 nameEntry ON by defaultOverlay reads the flag but never automatically enables it in a new session.
$Start of a code lineFollowed by the operation, address, and value fields.

Example file

EXAMPLE
# PCSH00297 Ys VIII CHT 1.02
_V0 EXTRA MAX
$A100 8124D8C6 0000BF00
_V1 SP Max
$3201 8148A1F0 00048240
$3300 00000000 00002710

Start each entry with _V0 or _V1. The following $ lines belong to that entry.

Notes
  • Z06 uses UTF-8. The old manual's ANSI requirement belongs to Z04. Overlay supports UTF-8 and GBK.
  • Example addresses explain the format; they are not universal cheats. The Title ID, game version, and actual memory layout must match.
02

$AAAA BBBBBBBB CCCCCCCC

Anatomy of a code line

Manual p. 4

Separate the three hexadecimal fields with spaces. AAAA has four digits; the other fields have eight each. Pad them even when writing only one byte.

The opcode determines what each field means. A copy uses the third field as a source address; a compressed write uses a parameter line for count and strides.

FORMAT
$AAAA BBBBBBBB CCCCCCCC
FieldMeaningDetails
AAAAOperation fieldCode family, width, controlled line count, or pointer depth.
BBBBBBBBAddress fieldUsually the destination; may also be a base address, mode, or stride.
CCCCCCCCValue fieldUsually the value; may also be a source address, offset, or button mask.
X = 0 / 1 / 2Common width selector8 / 16 / 32 bits. A 32-bit field can also store a floating-point bit pattern.

A 32-bit value

EXAMPLE
$0200 81481280 05F5E0FF

Opcode 0200 is a direct 32-bit write. 05F5E0FF is decimal 99,999,999.

Notes
  • All numbers are hexadecimal. For example, 0000000A means decimal 10.
  • Encode a 32-bit float as its IEEE 754 bit pattern: 1.0 is 3F800000. A decimal string in a code is not a floating-point conversion.
03

$0X00

Direct writes

Manual p. 5

Write one 8-, 16-, or 32-bit value to a data address. There is no parameter line.

FORMAT
$0X00 BBBBBBBB CCCCCCCC
FieldMeaningDetails
XWrite width0 = 8 bits; 1 = 16 bits; 2 = 32 bits.
00Associated linesAlways 00.
BBBBBBBBDestinationThe valid memory address to write.
CCCCCCCCValueUse the low 2 hex digits for 8 bits, the low 4 for 16 bits, or all 8 for 32 bits.

16-bit write

EXAMPLE
_V0 bait 990
$0100 83823288 000003DE

Write 0x3DE (decimal 990) as a 16-bit value at 0x83823288.

32-bit write

EXAMPLE
_V1 OR 99999999
$0200 81481280 05F5E0FF

Write the 32-bit encoding of decimal 99,999,999 at the destination.

Notes
  • Turning an ordinary data entry OFF stops future writes. It does not guarantee restoration of an earlier game value.
04

$5X00

Memory copies

Manual p. 6

Read a value from the source and write it to the destination. The third field is an address, not a literal value.

FORMAT
$5X00 BBBBBBBB CCCCCCCC
FieldMeaningDetails
XCopy width0 / 1 / 2 select 8 / 16 / 32 bits.
00Associated linesAlways 00.
BBBBBBBBDestinationThe value is written here.
CCCCCCCCSourceThe value is read here.

16-bit copy

EXAMPLE
_V0 Infinite Health
$5100 821F4FB8 821F4FB6

Read 16 bits at 0x821F4FB6 and copy them to 0x821F4FB8.

05

$4X01

Compressed writes

Manual p. 7

Express repeated writes in two lines. The first supplies the initial address and value; the second supplies the count and both strides. Do not interpret the parameter line as an independent opcode.

FORMAT
$4X01 BBBBBBBB CCCCCCCC
$NNNN SSSSSSSS VVVVVVVV
FieldMeaningDetails
XWrite width0 / 1 / 2 select 8 / 16 / 32 bits.
01Associated linesExactly one parameter line follows.
BBBBBBBB / CCCCCCCCInitial address / valueThe first write uses these values.
NNNNCountThe hexadecimal number of writes.
SSSSSSSSAddress strideThe difference between consecutive destinations, in bytes.
VVVVVVVVValue strideThe increment after each write; 0 keeps the same value.

Four consecutive writes

EXAMPLE
_V1 Unlock Galley
$4101 82CDE530 000000FF
$0004 00000006 00000001

Write four 16-bit values. Increase the address by 6 and the value by 1 each time.

Equivalent to these writes:

EQUIVALENT
$0100 82CDE530 000000FF
$0100 82CDE536 00000100
$0100 82CDE53C 00000101
$0100 82CDE542 00000102
06

$3XZZ

Pointer writes

Manual p. 8–9

Read a pointer at the base, add an offset, and repeat at each level. The final destination depends on the pointer values; it is not the sum of all offsets added to the base.

FORMAT
$3XZZ BBBBBBBB OOOOOOO1
$3X00 00000000 OOOOOOO2
…
$3300 00000000 CCCCCCCC
FieldMeaningDetails
XFinal write width0 / 1 / 2 select 8 / 16 / 32 bits.
ZZPointer depthThe number of pointer lines, excluding the final 3300 line.
BBBBBBBBBase addressWhere the first pointer is read.
OOOOOOOnOffsetsAdd each offset after reading that level's pointer.
3300Final write lineThe second field is 0; the third is the value to write.

Address resolution

  1. P1 = read32(8632AE30) + EA20
  2. P2 = read32(P1) + 100
  3. destination = read32(P2) + C4

A three-level pointer

EXAMPLE
_V1 CP 99,999
$3203 8632AE30 0000EA20
$3200 00000000 00000100
$3200 00000000 000000C4
$3300 00000000 0001869F

Read through the chain with offsets EA20, 100, and C4, then write decimal 99,999 as a 32-bit value.

07

$8XZZ / $8YZZ

Pointer copies

Manual p. 10–12

Resolve separate destination and source pointer chains, then copy the value between their final addresses. End the two chains with 8800 and 8900.

FORMAT
$8XZZ BBBBBBBB OOOOOOO1
$8X00 00000000 OOOOOOO2
…
$8800 00000000 00000000
$8YZZ DDDDDDDD PPPPPPP1
$8Y00 00000000 PPPPPPP2
…
$8900 00000000 00000000
FieldMeaningDetails
X = 0 / 1 / 2Destination width8 / 16 / 32 bits respectively.
Y = 4 / 5 / 6Source width marker8 / 16 / 32 bits respectively.
ZZDepth of each chainEach chain supplies its depth and offsets.
8800End of destination chainThe second and third fields are both 0.
8900End of source chainThe second and third fields are both 0.

Three-level, 16-bit pointer copy

EXAMPLE
_V0 INFINITE MAGIC USAGE
$8103 8789C5E4 00047E80
$8100 00000000 00000004
$8100 00000000 000002E8
$8800 00000000 00000000
$8503 8789C5E8 00000010
$8500 00000000 00000014
$8500 00000000 000002EC
$8900 00000000 00000000

The destination offsets are 47E80 → 4 → 2E8; the source offsets are 10 → 14 → 2EC. Copy the final 16-bit value.

Notes
  • The Z04 manual requires equal depths and widths for both chains. This example follows that rule; do not assume an older restriction defines every later implementation's capabilities.
08

$7XYY / $77ZZ

Compressed pointer writes

Manual p. 13–16

Combine a pointer chain with repeated writes. Repetition can change the base, an intermediate level, or the final level; it does not always change only the final destination.

FORMAT
$7XYY BBBBBBBB OOOOOOO1
$7X00 00000000 OOOOOOO2
…
$77ZZ 00000000 CCCCCCCC
$NNNN SSSSSSSS VVVVVVVV
FieldMeaningDetails
XWrite width0 / 1 / 2 select 8 / 16 / 32 bits.
YYPointer depthThe number of pointer lines, excluding 77ZZ and the parameter line.
ZZLevel to advance0 ≤ ZZ ≤ YY: 0 advances the base; YY advances the last level.
CCCCCCCCInitial valueIts width is selected by X in the first line.
NNNNRepeat countThe hexadecimal number of writes.
SSSSSSSS / VVVVVVVVAddress / value stridesAdvance the selected level and increment the write value.

Repeat at the final level

EXAMPLE
_V1 CP 99,999
$7203 85C0B048 00000100
$7200 00000000 000000D4
$7200 00000000 00000008
$7703 00000000 447A0000
$0004 00000008 00000000

A three-level chain with ZZ=3. The last offset is 8, 10, 18, then 20 (hexadecimal). Write the same 32-bit value each time.

Repeat at the first level

EXAMPLE
_V0 ITEM 96+
$7003 85C0B048 00010100
$7000 00000000 00000FD4
$7000 00000000 00000008
$7701 00000000 00000060
$0005 00000004 00000001

A three-level chain with ZZ=1. The first offset is 10100, 10104, 10108, 1010C, then 10110. Write 8-bit values 60 through 64, resolving the remaining chain again each time.

Repeat at the base

EXAMPLE
_V1 TP 9,999
$7104 82E40F10 00000000
$7100 00000000 00000E50
$7100 00000000 00000018
$7100 00000000 0000000C
$7700 00000000 0000270F
$0006 00000010 00000000

With ZZ=0, the bases are 82E40F10, 82E40F20, 82E40F30, 82E40F40, 82E40F50, and 82E40F60. Follow the four-level chain and write 16-bit 270F each time.

09

$AX00

Instruction writes

Manual p. 17

Patch instructions in the text segment. The manual defines 16- and 32-bit writes; choose the address and length for the actual ARM or Thumb instruction boundary.

FORMAT
$AX00 BBBBBBBB CCCCCCCC
FieldMeaningDetails
X = 1 / 2Write width16 / 32 bits respectively.
00Associated linesAlways 00.
BBBBBBBBDestinationThe instruction address to modify.
CCCCCCCCInstruction bit patternUse the low 4 hex digits for 16 bits or all 8 for 32 bits.

16-bit Thumb NOP

EXAMPLE
_V0 EXTRA MAX
$A100 8114C8A2 0000BF00

Write halfword BF00; its bytes in memory are 00 BF. This example is a Thumb NOP.

32-bit instruction pattern

EXAMPLE
_V1 Branch Test
$A200 81132EA8 BE12F075

Write numeric value BE12F075; the memory bytes are 75 F0 12 BE. Interpret the instruction using the actual instruction set and address.

Notes
  • ARM / Thumb storage here is little-endian. Supply the numeric bit pattern; do not reverse the number again.
  • Turning an A patch OFF releases it and restores its saved original bytes. B2 changes the address basis; it is not the restoration mechanism.
  • This section retains A100 / A200 as listed in the manual. Consult the relevant project version for additional subtypes.
10

$B2XX

Module-relative addressing

Z06 site §4.7

Z06 extends B2 to select a module index and segment. Relative addresses in following codes use that segment's current base, reducing dependence on a fixed load address.

FORMAT
$B2XX 0000000Y 00000000
FieldMeaningDetails
XXModule indexThe hexadecimal index in the low two opcode digits. It is not a module UID.
Y = 0seg0Usually the text segment.
Y = 1seg1Usually the data segment.
Final fieldReservedUse 00000000.

Module 0, text-segment patch

EXAMPLE
_V0 Max Gil After Using
$B200 00000000 00000000
$A100 001CD8C4 0000BF00

Write a 16-bit patch at module 0's seg0 base plus 001CD8C4.

Module 0, repeated data writes

EXAMPLE
_V0 All Item 99
$B200 00000001 00000000
$4001 00FFF96C 00000063
$006F 00000001 00000000

Select seg1, start at relative offset 00FFF96C, and write 8-bit 63 for 6F iterations with address stride 1.

Notes
  • Original Z06 dumps record module information in a matching .txt file. Dynamic loading/unloading can change indexes; an index is not a stable module identity.
  • A module base provides relative positioning, not a guarantee of equal offsets or instructions across different game versions.
11

$C2AA

Button conditions

Manual p. 18

The condition controls the next AA code lines. Combine button values with bitwise OR; for example, L + R is 00000300.

FORMAT
$C2AA 0000MMMM CCCCCCCC
FieldMeaningDetails
AAControlled line countThe hexadecimal number of following controlled code lines.
MMMMHistorical device modeThe Z04 definitions appear below. This is a version-dependent field.
CCCCCCCCButton maskCombine individual button values with bitwise OR.

Button masks

ButtonHexadecimal value
SELECT00000001
START00000008
↑ Up00000010
→ Right00000020
↓ Down00000040
← Left00000080
L00000100
R00000200
△ Triangle00001000
○ Circle00002000
× Cross00004000
□ Square00008000
No buttons00000000

Run three lines while holding L + R

EXAMPLE
_V0 EXTRA MAX
$C203 00000001 00000300
$0100 8109C5E4 00003846
$0100 8789C5E6 000000BF
$0200 8789C5E8 07F16307

Run the next three lines when the button condition matches; otherwise skip the controlled lines.

Notes
  • Z04 device modes: 0 no match, 1 Vita, 2 PSTV, 4 DualShock 3, and 8 DualShock 4.
  • Z06 / Overlay compare the complete button mask and do not identify the controller through the device field. Holding another button in addition to L + R is not the same combination.
  • Count physical code lines, including multiline parameters. Overlay menu input does not trigger game button conditions.
12

$DXAA

Memory comparisons

Manual p. 19

Read a value and compare it with the supplied value to decide whether the next AA lines run. X selects both the relation and the width, giving 12 combinations.

FORMAT
$DXAA BBBBBBBB CCCCCCCC
FieldMeaningDetails
XRelation / widthSelect a combination from the table below.
AAControlled line countThe hexadecimal number of following controlled lines.
BBBBBBBBAddress to compareWhere the value is read.
CCCCCCCCComparison valueA hexadecimal value or bit pattern of the selected width.

Comparison selectors

Relation8 bits16 bits32 bits
EqualX = 0X = 1X = 2
Not equalX = 3X = 4X = 5
Greater thanX = 6X = 7X = 8
Less thanX = 9X = AX = B

Write when a byte equals 5

EXAMPLE
_V0 GP999,999,999
$D001 81504000 00000005
$0200 81504780 3B9AC9FF

If the 8-bit value at 81504000 equals 5, write decimal 999,999,999 as 32 bits at 81504780. The write opcode corrects a typo in the original PDF.

Notes
  • Z06 / Overlay compare raw values at the selected width. Greater-than and less-than comparisons are unsigned integer comparisons, not floating-point arithmetic.
  • A failed condition skips its controlled range; unrelated following codes may still run. Nested counts must respect physical lines and multiline instruction boundaries.

Z04 → Z06 → Overlay

Version differences and errata

Manual and Z06 updates

This guide covers the original PDF's file structure, line layout, and all nine code families, plus the Z06 B2 update. Page references use the printed manual numbering; the PDF page index is one greater.

FieldMeaningDetails
EncodingZ04 → Z06ANSI belongs to Z04. The Z06 site specifies UTF-8; Overlay supports UTF-8 / GBK.
Automatic enablingOriginal → OverlayOriginal _V1 starts ON. New Overlay sessions start with every entry OFF.
CapacityVersion-specificThe PDF mentions 50 descriptions / 200 lines. The Z06 site specifies 50 groups with up to 200 lines each. Overlay uses separate limits.
B2Z06 additionThe module index is XX; the second field's Y selects the segment. Do not exchange them.
Pointer copiesZ04 restrictionThe manual requires equal chain depths and widths; this alone does not define later implementations.
Device modeZ04 table and later behaviorKeep the old mode table as a reference. Z06 / Overlay match the complete button mask.
Notes
  • The text-segment examples mix numeric bit patterns with byte order. This guide uses little-endian interpretation: BF00 produces bytes 00 BF; the value is not reversed again.
  • The condition example's $2000 conflicts with the direct-write format. It is explicitly corrected to $0200 here.
  • The third compressed-pointer example has a base-address mismatch in its comment. This guide follows 82E40F10 in the code rather than the stale comment.
  • This is a format reference. Older firmware requirements, group limits, or search features are not applied to VitaCheat Overlay.
